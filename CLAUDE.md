# Oni — правила работы для Claude

Источник правды между сессиями — **файлы в репозитории**: этот (правила, решения,
предпочтения; Claude Code читает его сам при каждом запуске) и `ROADMAP.md` (что сделано и что
осталось). Память Claude Code можно использовать, но только как дополнение и указатель на эти
файлы: если они расходятся, верны файлы.

## Что и где записывать (чтобы после перезапуска всё было известно)

| Что произошло | Куда записать |
| --- | --- |
| Задача начата / сделана / отложена | сводка в начале `ROADMAP.md` + пункт в нужном разделе |
| Изменение, которое увидит пользователь | `CHANGELOG.md`, «Не выпущено» (при выпуске — раздел версии) |
| Решение или предпочтение пользователя | этот файл, «Решения и предпочтения» |
| Новое правило работы, окружение, секрет, адрес | этот файл, «Как ведём работу» / «Окружение» |
| Почему сделано именно так | сообщение коммита и комментарий в коде |

Записывать в том же коммите, что и саму работу, и отправлять в `origin` — тогда на GitHub
всегда актуальное состояние.

## С чего начать

1. Прочитать **`ROADMAP.md`**: сводка в начале — что сделано, что в работе, что осталось.
2. `CHANGELOG.md`, раздел «Не выпущено» — что уже влито в `main`, но не выпущено.
3. Подробности решений — в разделах ROADMAP и в `docs/` (`recommendations.md`, `ios-signing.md`).

## Общение

- Все сообщения пользователю — **на русском**.
- Пользователь не программист-эксперт в деталях: объяснять по-человечески, без жаргона.

## Как ведём работу

- Одна задача — одна ветка `feat/…`, `fix/…` или `chore/…`; готовое сливается в `main`
  (`--ff-only`) и отправляется в `origin`, после — проверить CI (`gh run list`).
- Готово = проходят `npm run check` и `npm run test:e2e` (на реальном аккаунте, нужен
  `YANDEX_MUSIC_TOKEN` в окружении), пункт в ROADMAP отмечен, строка в CHANGELOG.
- Баг, найденный вручную, сначала воспроизводим тестом, потом чиним.
- Тесты не оставляют изменений в реальном аккаунте: лайки, переименования и т. п. сразу
  откатываются (в `finally`).
- Выпуск: раздел в CHANGELOG → `npm version x.y.z --no-git-tag-version` → коммит
  «Release x.y.z» → `git tag -a vx.y.z` → `git push --follow-tags` → `npm run release`
  (Windows, затем ждёт облачную сборку iPhone и прикладывает IPA + обновляет `sidestore.json`).
  Подробно — README, «Выпуск версии».
- Состояние проекта после работы — в сводку ROADMAP (что сделано / в работе / осталось).

## Окружение

- Код: **D4SuCE/oni** (GitHub). С 22.10.2026 на время разработки **публичный** (решение
  пользователя: минуты macOS бесплатны); вернуть в приватный — по его команде
  (`gh repo edit D4SuCE/oni --visibility private --accept-visibility-change-consequences`).
  Перед открытием история проверена: токена нет. Секреты в код и логи не класть. Выпуски: публичный **D4SuCE/oni-releases**
  (установщики Windows, IPA, `sidestore.json`, страница со скриншотами). Токен в программу не
  встраивается — поэтому выпуски отдельно (решение пользователя).
- Секрет репозитория `YANDEX_MUSIC_TOKEN` — для входа на iOS-симуляторе в CI (разрешено
  пользователем); из логов вычищается.
- CI: `.github/workflows/check.yml` (каждый push, Linux, дёшево) и `ios.yml` (минуты macOS ×10).
  По тегу `ios.yml` только собирает IPA (~1,5 мин ≈ 20 списанных); проверка на симуляторе (+3 мин,
  всего ≈ 50 списанных) — только вручную: `gh workflow run ios.yml --ref <ветка>` (по умолчанию
  `smoke=true`), один раз на партию iOS-правок перед выпуском. Не гонять её на каждую правку и не
  повторять «not acquired» без нужды. 22.10.2026 израсходовано 1 844 из 2 000 (письмо GitHub). Пока репозиторий публичный, минуты не списываются; прогоны iOS
  можно не экономить (но и не гонять впустую). Бюджет — `gh api users/D4SuCE/settings/billing/actions`
  (нужен `gh auth refresh -s user`).
- Папка данных Windows-версии — `%APPDATA%/Wave` (имя со старого названия, менять нельзя:
  потеряются вход и история).
- Сборка для себя: `npx electron-builder --win -c.directories.output=release/oni`
  (если папка занята запущенной копией — `release/oni-next`).
  Сборки не копить: `npm run release` сам удаляет установщики версии после выкладки (оставляет
  `notes.md`); сборки «для себя» удалять, когда проверены (22.10.2026 папка `release` весила 11 ГБ).
- Для установки SideStore на компьютере стоят iTunes и **iloader** (`%LOCALAPPDATA%/iloader`,
  winget `nabdev.iloader`) — по инструкции docs.sidestore.io. Тихая установка iTunes через winget
  не ставит Apple Mobile Device Support (без неё iloader не видит iPhone): её MSI достаётся из
  `iTunes64Setup.exe /extract` и ставится `msiexec /i AppleMobileDeviceSupport64.msi`.
- Официальное приложение Яндекс Музыки стоит у пользователя
  (`%LOCALAPPDATA%/Programs/YandexMusic`, Electron): адреса неизвестных запросов API можно найти
  в его `resources/app.asar` (так найден `ugc/tracks/<id>/change`).

## Решения и предпочтения пользователя

- iPhone — через **SideStore** (бесплатный Apple ID), не TestFlight. Свои часы Apple Watch,
  скорее всего, потребуют платного аккаунта — обсудить, когда дойдём.
- Рекомендации — уровня Spotify; японский стиль, палитра пользователя: фон #090909, панель
  #171514, стекло #211816, красный #D9272E / #8E171B, золото #C79A54, текст #F2EEE8 / #A7A3A0,
  обводки #49403D.
- Не нравятся: красные ползунки с золотым ободком, системные выпадающие списки. Ручка ползунка
  (красная, как в эквалайзере) — только при наведении.
- Кнопок «назад / вперёд» в меню нет (убраны по просьбе) — только мышь 4/5 и Alt+←/→.
- Арта для обложек «Открытий недели» и «Радара» не будет — остаются нарисованные;
  `video.mp4` из макета удалён.
- iPhone-раскладка — минималистичная, как у Яндекс Музыки по количеству кнопок: 4 вкладки внизу,
  поиск значком вверху справа; трек — одним нажатием, меню — долгим. Стили iPhone — только под
  `html.ios`: внешний вид на ПК (в том числе узкого окна) не менять.
- Фильтр повторов «Моей волны» — общий для аккаунта (ПК и телефон).
- iPhone играет своим плеером iOS (AVAudioEngine + системный эквалайзер), не WebKit — иначе экран
  блокировки «±10 с», задержка перемотки и тишина в фоне. Обновления на iPhone — сообщение в Oni
  и кнопка, открывающая SideStore с IPA (сам себя Oni поставить не может); «Автообновление» открывает
  SideStore само. LocalDevVPN включают/выключают автоматизации «Команд» на открытие/закрытие SideStore
  (у пользователя настроены; основной VPN у него — Happ).
- Скачивание списков — сверху вниз, как в Яндекс Музыке (22.10.2026; раньше по просьбе было «от старых
  к новым»); на треке — кружок, пока качается, стрелка — когда скачан, в очереди — ничего.
- Без сети — как в Яндекс Музыке: открывается «Мне нравится», скачанные играют в своих плейлистах;
  «Скачанное» — отдельная вкладка. Обрыв сети во время волны — скачанные вперемешку, потом снова волна.
- Меню трека повторяет официальное приложение (порядок пунктов; у своих загруженных mp3 —
  короткое меню, как у Яндекса).
- 22.10.2026 пользователь принял все предложенные улучшения (список — ROADMAP, «Этап 7») и добавил
  перестановку треков в своих плейлистах и «Мне нравится» на обеих платформах.
- После 1.9.0 (22.10.2026) из новых идей выбраны: виджет + кнопки (Пункт управления, экран блокировки,
  кнопка «Действие») и «Итоги года» историями; не нужны: эквалайзер под наушники, «Волна в дорогу»,
  Last.fm. Плюс доделать хвосты (пульсация на iPhone, порядок в ROADMAP).
- 22.10.2026: «Можешь не предлагать — делай что нужно». Готовое (тесты и облачная проверка iPhone прошли)
  вливать и выпускать без вопроса; спрашивать только то, что решает пользователь (вкусы, деньги, риск для
  его данных или установки).
- Каждый план и решение записывать в файлы (ROADMAP, CHANGELOG, этот файл) — пользователь
  хочет быть уверен, что после перезапуска сессии всё известно.
