# Автопилот: работа без пользователя (облако)

Тебя запускает облачный агент Claude Code (routine «Oni — разработка» на аккаунте d4suceusa, дважды в час — две
routine, каждая раз в час, со сдвигом на 30 мин) без пользователя: он не смотрит в чат. **Один запуск — одна задача** из списка «Автопилот» в
`ROADMAP.md`: длинные чаты дороги, поэтому сделал задачу (или кончился лимит) — всё сохранено, закончил.
Следующий запуск — новый чат, он продолжит по файлам.

Облако: GitHub — через посредника, открыт только `D4SuCE/oni`, GraphQL закрыт — `gh issue …` не работает,
задачи только через REST (`gh api repos/D4SuCE/oni/issues…`); `gh run`, `gh workflow run`, `gh api` работают.
В окружении есть `GH_TOKEN` и `YANDEX_MUSIC_TOKEN`. Токены никогда не печатать.
В `main` писать напрямую нельзя (с 28.10.2026) — только PR с зелёной `check`, через REST, как в `watch/AGENT.md`
(«В `main` писать напрямую нельзя»). Отметки `[~]` в ROADMAP — тоже маленьким PR.

## 0. Можно ли начинать

1. `date -u` (для отметок времени). С 25.10.2026 ночи автопилот работает всегда (решение пользователя: пока есть
   лимиты; кончились — запуск оборвётся, следующий после сброса продолжит по замку и отметкам `[~]`).
   Пользователь может параллельно работать с Claude у себя на ПК — над тем же списком: задача, взятая там, тоже
   отмечается `[~]` (ветка, кто взял) в `main`, такую не бери — бери следующую.
2. Замок — ветка `autopilot`, файл `lock.json` (`{"task": "...", "heartbeat": "<UTC>"}` или `{"task": null}`):
   `git fetch origin autopilot`. Если `task` не пустой и `heartbeat` моложе 45 минут — работает другой запуск:
   ответь «Занято» и закончи. Иначе (свободно или прошлый запуск оборвался, например, по лимиту) — возьми замок:
   новый коммит поверх `origin/autopilot` (ветки нет — создай с одним `lock.json`) и `git push origin
   HEAD:autopilot` **без** `--force`. Push отклонён — замок взял другой: закончи.
3. Обновляй `heartbeat` (коммит + push в `autopilot`) перед и после каждого долгого шага (облачные проверки,
   ожидание `gh run watch`) — не реже раза в 30 минут.
4. В конце (задача сделана или упёрлась) — `{"task": null}` в замок.

## 1. Какую задачу брать

`ROADMAP.md` → «Очередь задач»: первая не `[x]`; `[~]` с пометкой «на ПК» — её делают с пользователем, пропусти.
Иначе `[~]` — прошлый запуск оборвался: продолжи с его ветки
(`git branch -r`, отметка в ROADMAP «ветка …, сделано …, осталось …»). Все `[x]` — один раз напиши в задачу
автопилота «Список выполнен» (если ещё не писал) и закончи.

Перед работой: `CLAUDE.md` (правила и решения пользователя), сводка `ROADMAP.md`, нужный раздел ROADMAP.

## 2. Как делать

Как в CLAUDE.md, «Как ведём работу»: ветка `feat/…`/`fix/…`, `npm ci`, баг — сначала тест; код. Сохраняйся
часто: после каждого заметного шага — коммит, `git push -u origin <ветка>` и строка в ROADMAP у задачи
(`[~]`, ветка, что сделано, что осталось) — лимит может оборвать запуск в любой момент.

Готово = `npm run check`; e2e на Windows-машине GitHub: `gh workflow run e2e.yml --ref <ветка>`; если тронут
iPhone или общий плеер — облачная проверка: `gh workflow run ios.yml --ref <ветка>`; ждать —
`gh run list --workflow <файл> --branch <ветка> --limit 1`, `gh run watch <id> --exit-status`. Падают
нестабильные шаги `ios-pulse` / `fast-start` (медленные облачные Mac) — поправь их пороги (это пункт «Нестабильно»
в сводке ROADMAP), а не выключай. Красное — чини; не выходит — оставь в ветке, опиши в ROADMAP и в задаче.

Затем: ROADMAP (`[x]`, сводка), CHANGELOG «Не выпущено» в той же ветке, PR в `main` и слить (squash; если `main`
ушёл вперёд и есть конфликт — `git rebase origin/main` в ветке и снова проверки).

**Выпуск** — только если у задачи в списке написано «выпуск»: порядок из CLAUDE.md («Выпуск»; PATCH — исправления,
MINOR — новое), **без метки**: PR «Release x.y.z» (ветка `release/x.y.z`) и слить — метку `vx.y.z` ставит
и сборки запускает `tag-release.yml`. Следить за `tag-release`, потом
`release.yml` до конца (Windows + IPA + `sidestore.json`). Задачи «без выпуска»
(анимации) — пробная сборка, пользователь сам потрогает и выберет. Если выпуск запрещён фильтром или упал —
оставь всё готовым (PR или `main`), напиши, что осталось сделать пользователю.

Нельзя: печатать токены; `--force`, переписывать историю; выпускать с красными тестами; оставлять изменения
в аккаунте Яндекса (тесты откатывают в `finally`); брать вторую задачу в том же запуске; делать то, чего нет
в списке (идеи — в ROADMAP, «Идеи от сторожа», и в сообщение).

## 3. Сообщить пользователю

Одна задача GitHub с меткой `autopilot` (нет — создай: метку `gh api repos/D4SuCE/oni/labels -f name=autopilot
-f color=C79A54`, задачу `gh api repos/D4SuCE/oni/issues -f title="Oni — автопилот" -f body="…" -f
'labels[]=autopilot'`). По каждой задаче — комментарий по-русски, по-человечески, без жаргона: что сделано, вышла
ли версия (номер), что проверить на телефоне / ПК, что не получилось и почему. Пробная сборка — ссылка на
скачивание. Комментарий: `gh api repos/D4SuCE/oni/issues/<N>/comments -f body=@/tmp/comment.md`.
