# Oni (бывш. Wave) — план работ

Живой документ: обновляется в том же коммите, что и сама работа.
Статусы: `[ ]` не начато · `[~]` в работе · `[x]` готово.

## Как ведём проект

- Одна задача — одна ветка `feat/…` или `fix/…`, слияние в `main`, когда задача готова.
- Задача считается сделанной, когда проходят `npm run check` (typecheck + lint + тесты волны) и `npm run test:e2e`, а пункт здесь отмечен `[x]`.
- Баг, найденный вручную, сначала воспроизводим тестом, потом чиним.

- [x] «Коллекция» и «Мне нравится» открывали одну страницу, оба пункта подсвечивались.
      Теперь «Коллекция» — плейлисты, альбомы и исполнители, а «Мне нравится» — отдельная
      страница и карточка в плейлистах (как Liked Songs в Spotify).
- [x] Не показывались лайкнутые чужие плейлисты: приложение читало только
      `/playlists/list` (свои). Добавлены `/likes/playlists` в «Коллекции» и боковой панели
      (с именем владельца) и кнопка-сердечко на странице чужого плейлиста.
- [x] В боковой панели плейлисты сравнивались только по `kind`, а он у разных
      владельцев совпадает. Теперь — по `uid` + `kind`.
- [x] Контекстное меню закрывалось от прокрутки внутри самого меню, поэтому длинный
      список плейлистов в «Добавить в плейлист» нельзя было прокрутить.
- [x] Вход под своим аккаунтом, чтобы приложение можно было передать другу. Кнопка
      «Войти через Яндекс» была и раньше, но установленная версия подхватывала токен
      из переменной `YANDEX_MUSIC_TOKEN`, и «Выйти» не работало: после перезапуска
      приложение снова входило под тем же токеном. Теперь переменная читается только
      при разработке и в тестах. При выходе очищается и веб-сессия Яндекса, иначе
      следующий вход молча попадал в тот же аккаунт. На экране входа — подсказка про Плюс.
- [x] **История** — отдельный пункт в боковой панели (вместо раздела «Для вас» официального
      клиента: нужен был только ради истории). Две вкладки: «В этом приложении» — свой журнал
      (`src/player/recent.ts`, 500 последних прослушиваний, со временем и источником) и
      «Со всех устройств» — `/music-history` Яндекса (около 10 дней, по дням и источникам).
      Разделы «Концерты», «Книги и подкасты», «For you» не нужны — не делаем.
- Заметка: прослушивания плейлистов из Wave Яндекс в `/music-history` не показывает, хотя
  `/play-audio` (отчёт о прослушивании, как у официальных клиентов) принимает: он идёт в
  статистику и рекомендации Яндекса. Поэтому есть своя вкладка «В этом приложении».
- Заметка: `/likes/tracks` не отдаёт треки, ставшие недоступными (их сняли
  правообладатели), поэтому лайков меньше, чем в системном плейлисте «Мне нравится».

## Этап 1. Стабильность

Цель: любая ошибка видна и не убивает окно, установщик собирается.

- [x] **ErrorBoundary.** Упавшая страница показывает карточку ошибки, а боковая
      панель и плеер продолжают работать. Если упал весь интерфейс — экран
      «Что-то пошло не так» с кнопкой «Перезагрузить». Покрыто e2e-шагом.
- [x] **Журнал ошибок.** Ошибки интерфейса и main-процесса пишутся в
      `userData/logs/wave.log` (до 1 МБ плюс один предыдущий файл). Упавший процесс
      отрисовки main перезагружает сам. Кнопка «Открыть журнал» — в настройках
      и на экране ошибки.
- [x] **Запуск как обычной программы (.exe).** `npm run dist` собирает в `release/`
      установщик `Wave-Setup-<версия>.exe` (NSIS: ярлыки на рабочем столе и в «Пуске»,
      удаление через «Параметры → Приложения») и `Wave-<версия>-portable.exe`.
      Нарисована иконка (`build/icon.png`, `build/icon.ico`), сборка вынесена в `release/`,
      чтобы не конфликтовать с `dist/` от Vite. Зависимости интерфейса перенесены
      в devDependencies: Vite встраивает их в бандл, и в установщик не попадает лишний
      `node_modules`. Задан AppUserModelID для панели задач.
- [x] **Линтер.** `npm run lint` — oxlint (typescript-eslint не поддерживает
      TypeScript 7, а oxlint не зависит от пакета `typescript`). Правила хуков React
      плюс своё правило `wave/effect-block-body` (`lint/wave-plugin.js`): эффект с
      телом-выражением возвращает значение React'у как cleanup, ровно так упал «Поиск».
      `npm run check` = typecheck + lint + тесты волны.
- [x] **e2e на английском.** Шаг переключает язык в настройках, проходит настройки,
      главную, поиск, коллекцию и «Мне нравится» и ищет кириллицу в элементах самого
      интерфейса (заголовки, вкладки, кнопки, подсказки). Данные Яндекса не проверяются.
      На русском та же выборка находит 12 элементов — проверка не пустая.

## Этап 3. Рекомендации в духе Spotify

Цель: кроме «Моей волны», у пользователя есть персональные подборки и быстрый
путь «хочу ещё такого же». Подход повторяет устройство рекомендаций Spotify
(кластеры вкуса, недельные подборки, учёт пропусков) поверх данных Яндекса.
Проект решения и разбор того, как это работает у Spotify, — в
[docs/recommendations.md](docs/recommendations.md).

- [x] **Профиль вкуса** (`src/recs/profile.ts`): веса треков, исполнителей и жанров
      из лайков, плейлистов, дослушиваний и пропусков, с затуханием по времени.
- [x] **История для всех источников**, а не только для волны: пропуски и
      дослушивания в миксах, плейлистах, поиске.

- [x] **Радио от трека / исполнителя / альбома / плейлиста** (как «Go to song radio»).
      «Радио по треку» в меню трека, кнопка «Радио» на страницах исполнителя, альбома и
      плейлиста. Это та же волна с seed `track:<id>`, `artist:<id>`, `album:<id>`,
      `playlist:<uid>:<kind>`, поэтому фильтр повторов работает и тут. В плеере —
      «Радио: <название>».
- [x] **«Похожие треки»** — вкладка на экране «Сейчас играет» (`/tracks/<id>/similar`).
- [x] **Персональные плейлисты Яндекса** на главной (полка «Собрано Яндексом»): «Плейлист дня», «Дежавю»,
      «Премьера», «Тайник» — аналоги Daily Mix и Discover Weekly.
- [x] **«Радар новинок»**: свежие релизы любимых исполнителей за последние
      недели, собирается локально из лайкнутых исполнителей.
- [x] **Миксы «Для вас»** (как Daily Mix): лайкнутые треки группируются по
      жанрам и исполнителям, и каждая группа дополняется похожими треками.
- [x] **«Открытия недели»** (как Discover Weekly): 30 новых треков, найденных
      «голосованием» похожих от любимых треков, по одному на исполнителя,
      обновление по понедельникам.
- Реализовано: `src/recs/` (чистые функции, тесты `npm run test:recs`), полка «Для вас» на
  главной и страница подборки. На реальном аккаунте: 6 миксов по 50 треков, 30 открытий,
  35 новинок, сборка ≈5 с, кэш на день / до понедельника / до пятницы, кнопка «Обновить».
- [ ] Метрика качества: доля дослушанных треков по источникам (миксы, открытия, волна)
      в настройках — чтобы проверять, что подборки лучше волны.
- [ ] **Блок «Потому что вы слушали…»** на главной: подборка от недавно
      прослушанного исполнителя (из локальной истории волны).

## Этап 5. iOS

Собрать iOS-приложение можно только на macOS (Xcode). С Windows для этого
нужна облачная сборка (GitHub Actions на macOS-раннере). Подробности о подписи —
в [docs/ios-signing.md](docs/ios-signing.md).

- [ ] Вход: OAuth Яндекса через `ASWebAuthenticationSession` (in-app browser).
- [ ] Фоновое воспроизведение (`UIBackgroundModes: audio`) и экран блокировки

- [ ] CI-сборка IPA с автоматической подписью.

## Этап 6. Apple Watch Ultra

- [ ] **Управление с часов без отдельного приложения.** Как только iOS-версия передаёт трек
      в `MPNowPlayingInfoCenter` и слушает `MPRemoteCommandCenter` (этап 5), часы управляют
      ей через системное приложение «Исполняется»: пауза, треки, громкость колёсиком.
- [ ] **Пульт на часах** (SwiftUI, watchOS): обложка, лайк, дизлайк, запуск «Моей волны» и
      миксов; связь с iPhone через WatchConnectivity. Это нативное приложение: watchOS не
      запускает веб-интерфейс Wave.
- [ ] **Самостоятельное воспроизведение на часах** (LTE на Ultra, Bluetooth-наушники):
      клиент API Яндекса на Swift (токен передаётся с телефона через Keychain-группу или
      WatchConnectivity), `AVPlayer` с long-form audio, офлайн-загрузка миксов.
- [ ] **Подпись и установка**: приложение для часов входит в iOS-приложение и ставится
      вместе с ним. На практике — TestFlight или Xcode; SideStore/AltStore приложения для
      часов поддерживают плохо, поэтому нужен платный аккаунт разработчика
      (см. [docs/ios-signing.md](docs/ios-signing.md)).

## Известные ограничения

- Названия треков, альбомов и плейлистов приходят от Яндекса как есть: их не переводят.
- e2e-тест работает с реальным аккаунтом (лайк/дизлайк сразу откатываются,
  сигналы волны в тестовом режиме не отправляются).
- В `src/api/yandex.ts` и `electron/main.cjs` лежат публичные ключи
  официального клиента Яндекс Музыки. Если репозиторий станет публичным,
  нужно решить, оставлять ли их в коде.
